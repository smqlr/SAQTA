# Этап 3. Сортировка — протоколы

Главное — в [README](../README.md#этап-3-сортировка--спаси): формула, решения по видам техники, цифры.
Здесь — как устроены дерево разборки, стена с подсветкой и партии, и как обновлять цены.

| Папка | Что внутри |
| --- | --- |
| `model/sort-model.mjs` | прайсы скупщиков с номерами объявлений, медианы, решения дерева по видам техники, цифры пилота |
| `wall/saqta-wall.ino` | прошивка ESP32: подсветка над ящиками по командам из USB (в пилоте; на железе не проверена) |
| `../src/lib/sort.js` | дерево разборки: формула, перебор для проверки, план для вещи |
| `../src/data.js` → `SORT_BINS`, `SORT_TREES` | ящики с ценами и деревья разборки с массами и временем шагов |

## Дерево разборки

Узел дерева — вещь или её часть. У каждого узла есть ящик, куда он идёт целиком (`sell`). У вскрываемого узла есть шаг:
- `access` — открыли корпус: каждую часть берём (`take`, минуты) или оставляем внутри; что осталось, идёт в ящик узла;
- `split` — разборка «всё или ничего»: шаг разделяет узел на части.

Флаг `must` — после вскрытия часть снимается всегда. Это батарея (в шкаф с песком) и отщёлкнутая крышка.
Массы записаны только у листьев, масса узла — сумма листьев. Поэтому дерево всегда сходится с массой вида в модели команды.

Ценность узла: **V = max(m × цена ящика, Σ V(частей) − t × 60 ₸)** — снизу вверх.
`npm run sort-stage` сравнивает её с перебором всех вариантов разборки при случайных ценах, ставках и снятых деталях.

Связь с этапом 2:
- `part` — деталь, которую этап 2 может снять под заказ. Если она в банке деталей, в дереве её уже нет.
- `did` — какие вскрытия этап 2 при этом сделал. Второй раз за них не платим.
- Паспорт SAQTA Доктора: у Apple память и SSD распаяны, их узлов нет.

## Сортировочная стена

12 ящиков в порядке `SORT_BINS` — номер ящика = номер полоски светодиодов:

| № | Ящик | Контейнер |
| --- | --- | --- |
| 1 | ОЗУ | малый 23×21×16 |
| 2 | Платы телефонов | малый |
| 3 | Платы ноутбуков и SSD | большой 59×42×35 |
| 4 | Телефоны без батареи | большой |
| 5 | Провода и шнуры | большой |
| 6 | Бытовые платы | малый |
| 7 | Моторы и ТЭНы | большой |
| 8 | Алюминий | малый |
| 9 | Чёрный металл | большой |
| 10 | Остаток: пластик, матрицы | большой |
| 11 | Целиком переработчику | площадка у весов 300 кг |
| 12 | Аккумуляторы | металлический шкаф с песком |

Порядок работы техника:
1. Сканирует QR вещи. Приложение считает дерево с текущими ценами и деталями, снятыми на этапе 2.
2. Над ящиками загорается свет по порядку шагов. Красный — шкаф для батареи: она снимается первой.
3. Техник кладёт части. Мелкое (ОЗУ, платы) взвешивает на весах с шагом 1 г, остальное — на платформенных весах при отгрузке.
4. Когда ящик набрал партию, нажимает «Отгрузить партию». Паспорт партии печатается на принтере QR-этикеток, который уже есть в бюджете.

### Протокол подсветки (USB, 115 200 бод, строка с `\n`)

| Команда | Что делает |
| --- | --- |
| `L 5 11` | погасить прошлую вещь и зажечь ящики 5 и 11 зелёным |
| `H 12` | добавить ящик 12 красным: батарея, шкаф |
| `C` | погасить всё |
| `T` | тест: пробежать по всем ящикам |

Ответ прошивки — `OK` или `ERR <причина>`. Приложение в пилоте шлёт команды через Web Serial (Chrome и Edge, без интернета).
В прототипе стена показана на экране «Хаб».

## Паспорт партии

| Поле | Пример |
| --- | --- |
| Номер и QR | `P-0001`, QR `SAQTA:lot:P-0001` |
| Ящик и покупатель | «Платы ноутбуков и SSD» → скупщик плат |
| Вес | с весов, до грамма для ОЗУ и плат |
| Устройства | номера `D-…` всех вещей, чьи части в партии |
| Батареи | «нет» / «Li-ion внутри: N — упаковка UN3481» / «аккумуляторы — UN3480» |
| Категории РОП | вес по категориям постановления № 1250 — для партии «целиком переработчику» |

## Как обновить цены

1. В `model/sort-model.mjs` заменить или добавить прайс в `BOARD_BUYERS`, `METAL_BUYERS` или `CABLE_BUYERS`: номер объявления, город, дата, цена.
2. `node sort/model/sort-model.mjs` — новые медианы и решения дерева.
3. `npm run sort-stage` покажет, какие цены в `src/data.js` и какие цифры README разошлись с моделью.
