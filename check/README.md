## SAQTA Доктор

```bash
sh check/doctor/saqta-doctor.sh
```

```bash
sh check/doctor/saqta-doctor.sh --app dist/saqta.html
```

```powershell
powershell -ExecutionPolicy Bypass -File check\doctor\saqta-doctor.ps1
```

| Параметр (sh / ps1) | Что делает |
| --- | --- |
| без параметров | печатает паспорт и открывает хаб на сайте со ссылкой `#hub/doctor=…` |
| `--app ПУТЬ` / `-App ПУТЬ` | ссылка на офлайн-файл `saqta.html` с флешки (на Windows ссылка копируется: Windows отрезает `#…` у файловых ссылок — вставьте её в «Спроси устройство») |
| `--no-open` / `-NoOpen` | только напечатать ссылку |
| `--json` / `-Json` | только паспорт в JSON |
| `--full-serial` / `-FullSerial` | серийный номер целиком (по умолчанию — последние 4 знака) |

Пример — MacBook команды, 19.11.2026:

```text
SAQTA Доктор · Apple MacBook Pro (Mac16,8)
  Батарея: здоровье 88% (5499 из 6249 мА·ч), циклов: 238, чип bq40z651
  Группы ячеек, мВ: 4079 4095 4098
  Диск: APPLE SSD AP0512Z, SMART: в норме
  Блокировка активации включена: целым не продаём, только детали
  Прочитано за 359 мс
```

### Что читает

| Система | Батарея | Диск | Остальное |
| --- | --- | --- | --- |
| macOS | `ioreg -r -c AppleSmartBattery`: DesignCapacity, AppleRawMaxCapacity, CycleCount, DeviceName, PermanentFailureStatus, BatteryData → CellVoltage, Qmax, LifetimeData (температуры) | `system_profiler SPNVMeDataType` и `SPSerialATADataType`: модель, объём, SMART | `SPHardwareDataType`: модель, чип, память, серийный номер, блокировка активации |
| Linux | `/sys/class/power_supply/BAT*`: energy_ или charge_full_design и full, cycle_count, производитель, модель | `/sys/block/*` (без флешек), `smartctl -H -A`: здоровье, износ NVMe (Percentage Used), часы работы | `/sys/class/dmi/id`, `/proc/cpuinfo`, `/proc/meminfo`, `/etc/os-release` |
| Windows | WMI `root\wmi`: BatteryStaticData.DesignedCapacity, BatteryFullChargedCapacity, BatteryCycleCount; запасной путь — `powercfg /batteryreport /xml` | `Get-PhysicalDisk` (HealthStatus), `Get-StorageReliabilityCounter` (Wear, PowerOnHours — только от администратора) | `Win32_ComputerSystem`, `Win32_PhysicalMemory`, `Win32_Processor`, `Win32_BIOS`, `Win32_SystemEnclosure` |

SMART на Linux и износ на Windows видны только с правами администратора (`sudo sh …`, PowerShell «от имени администратора»). Без них диск попадёт в паспорт как «нет данных».

**Только железо.** Скрипты не читают файлы, имя пользователя и компьютера, ничего не стирают и не меняют.
Серийный номер — последние 4 знака, если не попросить целиком.

### Загрузочная флешка

Для запароленных ноутбуков: любой live-Linux со `smartmontools` и папкой `check/doctor` на флешке.
1. Загрузиться с флешки (меню загрузки — F12, F9 или Esc, зависит от производителя).
2. `sudo sh /путь/saqta-doctor.sh --app /путь/saqta.html` — паспорт откроется в офлайн-файле хаба.
3. Если BIOS не даёт загрузиться с флешки — устройство идёт путём «не включается».

Стирание данных делает отдельная станция стирания хаба, а не Доктор: NVMe Sanitize или ATA Secure Erase с проверкой,
неисправный носитель — физическое уничтожение (NIST SP 800-88, Purge и Destroy). Сертификат донору выдаёт приложение.

### Паспорт v1

Скрипт кладёт JSON в ссылку: `<приложение>#hub/doctor=<base64url(JSON в UTF-8)>`. Хаб принимает ссылку, `doctor=…`, голый base64url или JSON.

```json
{
  "saqta": 1,
  "tool": "saqta-doctor.sh 1.0 · macOS 15.6",
  "ms": 359,
  "device": { "kind": "laptop", "vendor": "Apple", "model": "MacBook Pro (Mac16,8)", "cpu": "Apple M4 Pro",
              "ramGB": 24, "serial": "...XXXX", "os": "macOS 15.6", "lock": "enabled" },
  "battery": { "unit": "mAh", "design": 6249, "full": 5499, "cycles": 238, "chip": "bq40z651",
               "cellsMv": [4079, 4095, 4098], "qmax": [6136, 6095, 6128], "tMaxC": 44, "tMinC": 3, "pf": 0, "src": "ioreg" },
  "disks": [ { "model": "APPLE SSD AP0512Z", "bus": "nvme", "gb": 500, "smart": "ok", "wearPct": null, "hours": null } ]
}
```

| Поле | Значение |
| --- | --- |
| `saqta` | версия формата, всегда 1 |
| `device.kind` | `laptop` или `desktop` |
| `device.lock` | блокировка активации: `enabled` — целым не продаём, только детали; `disabled`; `null` — неизвестно (Windows, Linux) |
| `battery` | `null`, если батареи нет или чип не ответил |
| `battery.unit` | `mAh` (macOS) или `mWh` (Windows, большинство Linux); здоровье = full / design — единица не важна |
| `battery.cellsMv` | напряжение каждой последовательной группы ячеек, мВ (macOS) |
| `battery.qmax` | химическая ёмкость каждой группы, которую измерил газомер TI Impedance Track (macOS) |
| `battery.pf` | аварийный флаг чипа: не 0 — пакет не вскрываем |
| `disks[].smart` | `ok`, `fail` или `unknown` |

Хаб отклоняет паспорт без `"saqta": 1`, без двух ёмкостей или с текущей ёмкостью больше заводской в 1,5 раза.

## Ридер чипа батареи (ноутбук не включается)

ESP32-S3 из строки бюджета «Диагностика и ТЕСТ-30» читает пакет напрямую по SMBus — так же, как открытый проект PackProbe.
- **Провода:** SDA, SCL и минус пакета — три провода; подтяжка 4,7 кОм к 3,3 В. Распиновку разъёма берём по маркировке пакета или ищем мультиметром.
- **Адрес** умной батареи — 0x0B. Регистры Smart Battery Data Specification:

| Регистр | Что | Единица |
| --- | --- | --- |
| 0x08 | Temperature | 0,1 К |
| 0x09 | Voltage | мВ |
| 0x10 | FullChargeCapacity | мА·ч или 10 мВт·ч |
| 0x16 | BatteryStatus | флаги тревог |
| 0x17 | CycleCount | циклы |
| 0x18 | DesignCapacity | мА·ч или 10 мВт·ч |
| 0x1C, 0x20, 0x21 | SerialNumber, ManufacturerName, DeviceName | — |

- Некоторые пакеты спят. Будит их короткое зарядное напряжение от лабораторного блока питания с ограничением тока — это делает только мастер.
- Ответ ридера — те же поля, что в `battery` паспорта; источник `"src": "smbus"`.

## ТЕСТ-30: стенд для ячеек

16 каналов. Канал: держатель ячейки → INA219 (шунт 0,1 Ом) → MOSFET-ключ → резистор 2 Ом / 10 Вт → минус;
термодатчик NTC прижат к ячейке. 16 INA219 подключены через 2 мультиплексора I²C TCA9548A (адреса INA219 повторяются).
Напряжение ячейки = напряжение шины + падение на шунте, поэтому шунт в R не входит.

**Протокол — 30 с на 16 ячеек сразу:**
1. 0–4 с — покой: U покоя (среднее нескольких замеров). Ниже 2,5 В → C, ключ не включаем.
2. 4 с — ключ включён: ток ≈ 1,85 А.
3. 5 с — U через 1 с: R = (U покоя − U через 1 с) / I. По двум точкам, как метод DC в IEC 61960 (там 0,2C 10 с и 1C 1 с; у нас первая точка — покой).
4. 4–24 с — импульс 20 с; нагрев по NTC больше 2 °C → C.
5. 24–30 с — восстановление, кривая сохраняется в журнал.

**Калибровка каждое утро.** Стенд подключён двумя проводами: провода и пружины держателя добавляют 20–30 мОм.
Одна эталонная ячейка проходит все 16 слотов; разница её R в слоте и в эталонном слоте — поправка этого слота.
Эталон раз в неделю сверяем тестером YR1035+.

**Решение по ячейке:**
1. U < 2,5 В или нагрев больше 2 °C → **C**.
2. Медиана R соседей по пакету (только безопасные ячейки). R больше медианы в 1,3 раза → ёмкость не наследуется.
3. Здоровье = здоровье пакета из чипа (оценка снизу), если ячейка не выбивается; иначе — неизвестно.
4. Здоровье известно: **A** — ≥ 80% и R ≤ 80 мОм; **B** — ≥ 65% и R ≤ 150 мОм; иначе **C**.
5. Здоровье неизвестно: R > 150 мОм → **C**, иначе **спорная** → полный цикл Lii-500.
6. R ближе 10 мОм к порогу 80 или 150 мОм → переставить ячейку и измерить ещё раз, берём среднее.

**После стенда.** A и B — 7 дней на полке при 30–50% заряда, затем мультиметр: просадка больше 0,05 В → C.
Спорные — Lii-500: заряд и разряд с подсчётом мА·ч, ≈ 8 ч, только в рабочее время.

**Безопасность.** На стенде не заряжаем. Предохранитель в каждом канале. Лоток — металлический.
Вздутые ячейки до стенда не доходят — их забирает приём.

## Гарантия как датчик

Для каждого вида проверки (экран блокировки, Доктор, ТЕСТ-30 по грейдам) храним два счётчика: сколько деталей,
прошедших эту проверку, отработали 30 дней гарантии и сколько вернули. P(работает | прошла проверку) = (1 + отработали) / (2 + всего) —
среднее бета-распределения. Если доля возвратов у проверки выше 3% на последних 50 продажах — порог ужесточаем
(например, A с 80 мОм до 70 мОм) или добавляем ступень. Так хаб калибрует себя сам.
